## Clean Uninstall Best Practices in Windows — Revo, BCU, Geek Uninstaller, IObit, and Windows Internals

### 1. Bulk Crap Uninstaller (BCU) — read from source, `BCUninstaller/Bulk-Crap-Uninstaller`, path `source/UninstallTools/`

**Architecture**: `JunkManager.cs` uses reflection (`ReflectionTools.GetTypesImplementingBase<IJunkCreator>()`) to auto-discover every scanner class implementing `IJunkCreator`, calls `Setup(allUninstallers)` on each, then runs each scanner's `FindJunk()` per target app. Results go through `CleanUpResults`: dedup + confidence aggregation, self-protection (never flag the app's own live files), and exclusion of protected/system paths. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/JunkManager.cs)

**Junk scanner inventory** (`source/UninstallTools/Junk/Finders/` and `Junk/*.cs`, confirmed via GitHub API directory listing https://api.github.com/repos/BCUninstaller/Bulk-Crap-Uninstaller/contents/source/UninstallTools/Junk):

- `ProgramFilesOrphans.cs` (top-level, not under Finders) — recursively walks every Program Files directory looking for folders that don't map to any known install/uninstaller location, aren't named after an installed publisher/product, and aren't system-reserved. Score adjusted by folder depth, emptiness, presence of `.exe` files, subdirectory count, file count >100.
- `Finders/Drive/CommonDriveJunkScanner.cs` — generic "does this path belong to the target's install dir" filesystem check.
- `Finders/Drive/InstallLocationScanner.cs` — checks the registry-recorded install location itself still exists as a leftover dir.
- `Finders/Drive/PrefetchScanner.cs` — scans `%WINDIR%\Prefetch` for `.pf` files referencing the app's executable.
- `Finders/Drive/SpecificUninstallerKindScanner.cs` — matches by known uninstaller-type patterns (e.g., leftover NSIS/Inno uninstaller stub files).
- `Finders/Drive/UninstallerLocationScanner.cs` — flags the uninstaller executable file itself if left behind after the entry disappears.
- `Finders/Drive/WerScanner.cs` — Windows Error Reporting (`WER`) crash-dump/report folders tied to the app.
- `Finders/Misc/ShortcutJunk.cs` — checks 4 locations: user Programs folder, All-Users Programs folder, user Desktop, All-Users Desktop; parses `.lnk` target path against the app's install/uninstall path (special-cased for Steam app IDs since Steam shortcuts share one exe across many games). (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Finders/Misc/ShortcutJunk.cs)
- `Finders/Misc/StartupJunk.cs` — Startup-folder / Run-key style entries pointing at the install dir.
- `Finders/Registry/AppCompatFlagScanner.cs` — `AppCompatFlags\Layers`/compatibility-shim entries referencing the app's exe path.
- `Finders/Registry/AudioPolicyConfigScanner.cs` — `HKCU\...\Internet Explorer\LowRegistry\Audio\PolicyConfig\PropertyStore`; flags subkeys whose default value contains the app's install path. (fetched directly)
- `Finders/Registry/ComScanner.cs` — walks `HKLM/HKCU\SOFTWARE\Classes` and the `WOW6432Node` mirrors: CLSID → `InprocServer32`/`LocalServer32` target path, TypeLib registrations (32/64-bit paths), Interface → `ProxyStubClsid32`, ProgID/VersionIndependentProgID chains, and file-extension `ShellEx`/`PersistentHandler`/`OpenWithProgIDs` handlers — flags any COM object whose backing DLL/EXE sits inside the target's install directory, excluding system GUIDs/paths.
- `Finders/Registry/DebugTracingScanner.cs` — debug/tracing registry entries.
- `Finders/Registry/EventLogScanner.cs` — `SYSTEM\CurrentControlSet\Services\EventLog\Application`; matches source name to product name and verifies `EventMessageFile` path is inside the install dir before flagging as safe-to-remove.
- `Finders/Registry/FirewallRuleScanner.cs` — `HKLM\SYSTEM\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy\FirewallRules`; parses the `|App=...|` token out of each rule value (expanding env vars) and flags rules whose app path is inside the target's install location, confidence = `ExplicitConnection`.
- `Finders/Registry/HeapLeakDetectionScanner.cs` — Application Verifier / heap-leak-detection per-exe registry entries.
- `Finders/Registry/InstallerFoldersScanner.cs` — `SOFTWARE\Microsoft\Windows\CurrentVersion\Installer\Folders`; flags installer-cache path entries under the target's install dir, but adds `DirectoryStillUsed` (negative) confidence if another installed app also references the same path.
- `Finders/Registry/RegisteredApplicationsFinder.cs` — `RegisteredApplications` (default-programs registration) entries.
- `Finders/Registry/SoftwareRegKeyScanner.cs` — the generic `HKLM/HKCU\SOFTWARE\<Vendor>\<Product>` per-app settings key.
- `Finders/Registry/TracingScanner.cs` — `SOFTWARE\Microsoft\Tracing` entries.
- `Finders/Registry/UninstallerKeySearcher.cs` — Windows Installer product registration under `SOFTWARE\Classes\Installer\Products/Features/Patches` plus per-SID `...\Installer\UserData`; matches directly by the app's own uninstall key surviving, or converts an MSI bundle-provider key to an UpgradeCode and searches for matches (`ExplicitConnection`).
- `Finders/Registry/UserAssistScanner.cs` — `UserAssist` (execution-history / ROT13-encoded run-count) entries referencing the app.

**Confidence system** (`source/UninstallTools/Junk/Confidence/`):
- `ConfidenceLevel.cs` enum: `Unknown=0, Bad=5, Questionable=7, Good=9, VeryGood=12`, each with a `LocalisedName` for UI display. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Confidence/ConfidenceLevel.cs)
- `ConfidenceRecords.cs` defines named, reusable point deltas summed per item — verbatim table:
  - `CompanyNameDidNotMatch: -2`, `CompanyNameMatch: +4`, `AllSubdirsMatched: +4`, `DirectoryStillUsed: -7`, `ExplicitConnection: +4`, `ItemNameEqualsCompanyName: -2`, `ProductNameDodgyMatch: -2`, `ProductNamePerfectMatch: +2`, `QuestionableDirectoryName: -3`, `IsUninstallerRegistryKey: +20`, `IsStoreApp: -10`, `IsEmptyFolder: +4`, `ExecutablesArePresent: -4`, `FilesArePresent: 0`, `ManyFilesArePresent: -2`, `ProgramNameIsStillUsed: -4`, `FolderHasNoSubdirectories: +2`, `PublisherIsStillUsed: -4`, `UsedBySimilarNamedApp: -2`, `DirectlyInsideKnownFolder: -1`. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Confidence/ConfidenceRecords.cs)
  - `ConfidenceGenerators.cs`: computes product-name string similarity via the Sift4 distance algorithm (rejects if difference > `lowestLength/3`; classifies `PerfectMatch` vs `DodgyMatch`), applies a path-depth penalty (`2 - |level|*2`), checks company-name-equals-product-name, checks whether the publisher string appears in the parent path, and runs `TestForSimilarNames()` which penalizes every match except the single best one with `UsedBySimilarNamedApp` to stop cross-contamination between similarly named apps. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Confidence/ConfidenceGenerators.cs)
  - `ConfidenceCollection.cs` sums all attached `ConfidenceRecord.Change` values into a raw integer (`GetRawConfidence`, "0 is a mid-point") and maps that sum onto the `ConfidenceLevel` enum bands to classify an item as Bad/Questionable/Good/VeryGood; `GetWorstOffender()` surfaces the single most negative factor for UI display. Net effect: Microsoft/Windows-owned keys and shared/common-type Classes entries never accumulate the matching factors (no company/product-name hits, `DirectoryStillUsed` triggers), so they naturally stay Unknown/Bad and are excluded from auto-selection. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Confidence/ConfidenceCollection.cs)

**Deletion safety**: `RegistryKeyJunk.Delete()` calls `DeleteSubKeyTree()` directly — no automatic backup; a separate `Backup()` method exports the key to a `.reg` file only if invoked (BCU's UI prompts users to back up the registry before a batch run). `FileSystemJunk.Delete()` explicitly uses `RecycleOption.SendToRecycleBin` for both files and folders — permanent delete only occurs if the Recycle Bin is disabled/out of space. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Containers/RegistryKeyJunk.cs, https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Junk/Containers/FileSystemJunk.cs)

**Quiet uninstall execution**: BCU primarily *consumes* a `QuietUninstallString` value read straight from the registry via `RegistryFactory.GetQuietUninstallString()` (which also checks a `QuietUninstallString_hidden` fuzzy variant), rather than synthesizing silent switches itself for arbitrary installers — this only works when the original installer author populated that registry value. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Factory/RegistryFactory.cs) For MSI it has a dedicated `MsiUninstallModes` enum (`InstallModify / Uninstall / QuietUninstall`) and its own MSI code path invoking `msiexec` with quiet/no-restart flags (its handling of MSI bundles was seen using `/qb ... REBOOT=ReallySuppress /norestart` style calls). (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Uninstaller/MsiUninstallModes.cs; https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/ApplicationUninstallerEntry.cs) `UninstallerType.cs` enumerates the 14 kinds it recognizes: `Unknown, Msiexec, InnoSetup, Steam, Nsis, InstallShield, SdbInst, WindowsFeature, WindowsUpdate, StoreApp, SimpleDelete, Chocolatey, Oculus, PowerShell`. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/UninstallerType.cs)

**Process-tree handling**: `BulkUninstallEntry.cs` tracks the uninstaller's spawned child processes (plus, for MSI, all system-wide `msiexec` processes), detects "stalled" processes via performance counters (CPU ≤1%, I/O ≤10KB/s over 1.1s, killed after 30 idle iterations), and filters out benign processes like `explorer`. (https://raw.githubusercontent.com/BCUninstaller/Bulk-Crap-Uninstaller/master/source/UninstallTools/Uninstaller/BulkUninstallEntry.cs)

### 2. Revo Uninstaller

- **Scan modes**: Safe = fastest, registry + disk scan for the most obvious/clearly-identifiable leftovers; Moderate (recommended default) = Safe + extended scan of "most common places"; Advanced = deepest, most exhaustive scan of registry and filesystem, slowest, more false positives requiring user judgment. (https://www.revouninstaller.com/online-manual/uninstaller/, https://blog.gridinsoft.com/revo-uninstaller-safe-leftovers/)
- **Bold entries**: in the leftover list, items shown in **bold** are those Revo actually logged/traced as created by the target program; non-bold items are shown for context only and are *not* deleted even if checked — a key safety nuance easy to miss. Red-highlighted registry entries are marked "never delete." (https://www.revouninstaller.com/online-manual/uninstaller/)
- **Tracing / install monitoring**: "Install with Revo Uninstaller Pro" launches the target's setup under a live monitor that records every registry/file-system change as it happens into a "Traced Log," producing a much higher-confidence future removal than heuristic scanning, since it has ground truth rather than guesswork. (https://www.revouninstaller.com/how-to/trace-a-program-with-revo-uninstaller-pro/)
- **Forced Uninstall**: a separate module for programs whose built-in uninstaller is missing, broken, or only partially removed — directly purges registry/Add-Remove-Programs traces and known file locations without relying on the vendor's uninstaller at all. (https://www.revouninstaller.com/how-to/use-forced-uninstall/)
- **Backup/restore**: by default creates a Windows System Restore Point before any uninstall (if System Restore is enabled), and optionally a full Registry backup (restorable via its Backup Manager or the Windows Recovery Console). (search results citing revouninstaller.com manuals)

### 4. Windows internals a clean-uninstall tool must handle

- **Uninstall registry**: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`, its `WOW6432Node` mirror for 32-bit apps on 64-bit Windows, and `HKCU\...\Uninstall` for per-user installs. (https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key)
- **MSI**: silent removal is `msiexec /x {ProductCode} /qn` (optionally `/l*vx log.txt` for logging). (https://www.advancedinstaller.com/how-to-uninstall-msi-package.html) MSI also tracks state under `HKCR\Installer\Products\<packed/compressed GUID>` (a byte-reversed, base16-to-base85-ish "compressed GUID" transform of the ProductCode) and `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Installer\UserData\<SID>\Products\<ProductSquid>` (with `\Patches` for updates), plus `...\Installer\UpgradeCodes` (also stored "scrambled") and `...\Installer\UserData\S-1-5-18\Components` for per-component install records — all of this must be reconciled, not just the visible Uninstall key, or Windows Installer will report the product as still present. (https://installpac.wordpress.com/2008/03/31/packed-guids-darwin-descriptors-and-windows-installer-reference-counting/, search results on UserData/Products/UpgradeCodes/Components)
- **SharedDLLs refcounting**: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\SharedDLLs` stores a path→refcount map; every installer that shares a DLL is supposed to increment on install and decrement on uninstall, and the file is only actually deleted when the count reaches zero. A cleaner tool must decrement (not blindly delete count-anything files), because premature deletion breaks other apps still holding a live reference, while failing to decrement leaves an inflated count that blocks legitimate future cleanup. (https://www.revenera.com/blog/software-installation/cleaning-up-your-shared-dlls-registry-references-for-msis/, search result summaries)
- **App Paths**: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\<exe>` maps an exe name to its full path (and prepends to per-process `PATH`) so Explorer's Run box / `ShellExecute` can find it without touching the system `PATH`; leftover entries here point Explorer/Run at deleted binaries. (https://learn.microsoft.com/en-us/windows/win32/shell/app-registration)
- **File associations / COM**: extension ownership lives in `HKCR\.ext` → ProgID, `HKCR\<ProgID>`, plus `OpenWithProgIDs` (alternate handler list feeding the "Open With" menu) and the user-level override in `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.ext\OpenWithProgids` / `UserChoice`, which supersedes the machine-wide HKCR mapping for the logged-on user. COM registrations (`CLSID\{guid}\InprocServer32` / `LocalServer32`, `TypeLib`, `Interface\{guid}\ProxyStubClsid32`, `AppID`) mirror into `SOFTWARE\Classes` and its `WOW6432Node` twin for 32-bit COM servers on 64-bit Windows — an orphaned `InprocServer32` pointing at a deleted install dir will produce "class not registered" errors elsewhere until removed. (https://learn.microsoft.com/en-us/answers/questions/2851068/windows-file-association-explained-for-desktop-adm, https://learn.microsoft.com/en-us/windows/win32/shell/fa-progids)
- **Services/drivers**: `sc delete <name>` removes the service subkey cleanly; each service/driver also has a raw key at `HKLM\SYSTEM\CurrentControlSet\Services\<name>` that a broken uninstaller may leave behind if `sc delete` isn't run (manual key deletion plus reboot is the documented fallback). (https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/sc-delete)
- **Autostart entries**: `HKLM/HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` and `RunOnce` (RunOnce entries self-delete after execution by default); the *enabled/disabled* state shown in Task Manager's Startup tab is tracked separately in binary values under `...\Explorer\StartupApproved\Run`, `\Run32`, and `\StartupFolder` (first byte `02` = enabled) — deleting the Run value without also clearing the matching StartupApproved entry can leave stale metadata. (https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys, search summary on StartupApproved)
- **Scheduled tasks**: `schtasks /Delete /TN "<path>\<name>" /F` removes a task non-interactively; tasks are commonly named after or containing the vendor/product name so string-matching against the install path/publisher is the practical detection heuristic (mirrors BCU's approach elsewhere). (https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/schtasks-delete)
- **Firewall rules**: rules live at `HKLM\SYSTEM\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy\FirewallRules` (each value string contains an `|App=<path>|` token — exactly what BCU's `FirewallRuleScanner` parses) and can be removed either via that registry value or programmatically via the `INetFwPolicy2` COM interface's `Rules` collection, or from the command line with `netsh advfirewall firewall delete rule name=<n> program="<path>"`. (https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/netsh-advfirewall-firewall-control-firewall-behavior, https://learn.microsoft.com/en-us/windows/win32/api/netfw/nf-netfw-inetfwauthorizedapplications-remove)
- **Shell extensions**: context-menu and other shell handlers register under `HKCR\<FileType>\shellex\ContextMenuHandlers\<Name or GUID>`, resolving to `HKCR\CLSID\{guid}\InprocServer32`; Microsoft's own recommended *safe disable* pattern is to prefix the CLSID value with an invalid character (so it fails to parse) rather than delete it outright, reversible by removing the prefix — full removal deletes both the CLSID key and the ContextMenuHandlers subkey. There's also an "Approved Shell Extensions" allow-list Explorer consults. (https://devblogs.microsoft.com/oldnewthing/20151208-00, https://learn.microsoft.com/en-us/windows/win32/shell/reg-shell-exts)
- **Explorer caches**: `MuiCache` (under `HKCR\Local Settings\Software\Microsoft\Windows\Shell\MuiCache`, or per-user `HKCU\Software\Classes\Local Settings\...`) caches an exe's friendly description string and can be safely cleared for uninstalled apps; `AppCompatFlags\Layers` stores per-exe compatibility-shim settings (exactly what BCU's `AppCompatFlagScanner` targets). (Microsoft Q&A result cited above)
- **Other users' hives**: a currently logged-off user's `HKCU` equivalent lives on disk as `<profile>\NTUSER.DAT`; a thorough cleaner must `RegLoadKey` (or PowerShell's `reg load`) that hive under a temporary key, edit it, then unload — logged-in users' hives can't be loaded this way (file is locked), so this only reaches *inactive* profiles; forgetting this step leaves leftovers in every non-active user profile. (https://smallvoid.com/article/winnt-offline-registry-edit.html, https://www.pdq.com/blog/modify-the-registry-of-another-user/)
- **MSIX/UWP**: these are not registry/Program-Files apps at all — clean removal is `Get-AppxPackage -AllUsers -Name "*App*" | Remove-AppxPackage -AllUsers` (removes for every existing profile) and, to also stop it being provisioned into *new* profiles, `Remove-AppxProvisionedPackage` (DISM) against the Windows image — the two cmdlets are commonly confused and neither alone gives a "for all past and future users" clean state. (https://learn.microsoft.com/en-us/powershell/module/appx/remove-appxpackage, https://learn.microsoft.com/en-us/powershell/module/dism/remove-appxprovisionedpackage)
- **Uninstallers that spawn children / reboot-pending deletes**: an uninstaller often exits itself immediately after launching a worker/helper process, so a cleaner must walk the live process tree (as BCU does) rather than trust the parent's exit code. Files still locked at delete time get scheduled via `MoveFileExW(..., MOVEFILE_DELAY_UNTIL_REBOOT)`, which appends a `REG_MULTI_SZ` entry to `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\PendingFileRenameOperations` (`src\0\0` = delete-on-reboot, `src\0dst\0` = rename-on-reboot), processed in order at next boot — a tool should surface/allow reviewing this queue rather than silently leaving it. (https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)
- **Silent uninstaller conventions by installer framework** (used to build a "quiet uninstall" invocation when no `QuietUninstallString` registry value exists): Inno Setup — `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` on `unins000.exe` (VERYSILENT hides the progress window entirely; SUPPRESSMSGBOXES only matters combined with SILENT/VERYSILENT; NORESTART blocks an automatic reboot). (https://jrsoftware.org/ishelp/topic_uninstcmdline.htm) NSIS — `uninst.exe /S` (silent mode; must pass `_?=$INSTDIR` if launched via `ExecWait` to make it actually block/wait). (https://nsis.sourceforge.io/Reference/SilentUnInstall) InstallShield (InstallScript MSI style) — `Setup.exe /s /f1"<path>\response.iss"` (optionally `/f2<logfile>`); the `.iss` response file is first recorded by re-running setup with `/r`. (https://docs.revenera.com/installshield26helplib/helplibrary/SilentUninstall.htm)

### 5. Install-time snapshot/tracing vs. after-the-fact heuristic scanning — trade-offs

- **Tracing (Revo's "Traced Programs", generic install-monitor tools)**: captures ground truth — every registry write and file drop the installer actually performed — so removal confidence is near-total and false positives are rare. Downside: only works for apps installed *after* the tracer was set up (no retroactive coverage), consumes disk/CPU during every monitored install, can miss changes made by a delayed/background service after the installer process exits, and is defeated by installers that stage payloads through a temp elevation helper the monitor doesn't hook.
- **Heuristic post-hoc scanning (BCU, Geek, IObit "powerful scan")**: works retroactively on anything already installed or even already (badly) uninstalled, no setup step required, and can be run in bulk across dozens of apps at once. Downside: inherently probabilistic — name/publisher/path-similarity matching (as detailed in BCU's `ConfidenceGenerators`) can both over-flag legitimate shared components and under-flag renamed/obfuscated leftovers; this is exactly why these tools gate deletion behind a confidence score and default UI selection rather than auto-deleting everything found.
- Revo's Forced Uninstall and Geek/IObit's Force modes are a third, narrower strategy: they don't scan for *general* leftovers, they specifically target the case where the uninstall registry entry/uninstaller itself is gone or broken, directly removing the stub entry and known common leftover locations.

### 6. Consensus safety rules across all four tools

- Never delete or flag entries clearly owned by Microsoft/Windows, `SOFTWARE\Classes` entries for common shared file types, or VC++ redistributable / .NET runtime keys — BCU encodes this implicitly (Microsoft/system paths never accumulate matching-name/publisher confidence factors and carry heavy negative weights like `IsStoreApp: -10`, `DirectoryStillUsed: -7`), Revo encodes it explicitly (never lists an item if deleting it "could harm your system," red = never delete).
- Create a System Restore Point and/or registry backup before any batch deletion (Revo does this by default; BCU offers `.reg` export before deletion, separate from the delete call itself).
- Route file deletions through the Recycle Bin rather than permanent delete when possible (BCU's `FileSystemJunk` explicitly uses `RecycleOption.SendToRecycleBin`), reserving permanent removal for registry keys (which get `.reg` backups instead) since there's no registry "Recycle Bin".
- Distinguish "logged as created by this app" (Revo's bold, BCU's `ExplicitConnection`/`IsUninstallerRegistryKey` high-confidence factors) from "merely looks related" (Revo's non-bold, BCU's low/`Questionable`/`Bad` band) and require explicit user review before deleting anything in the lower-confidence tier — none of the four tools auto-deletes low-confidence items without a checkbox the user must tick.
- Prefer the vendor's own quiet-uninstall path (registry `QuietUninstallString`, MSI ProductCode) over guessing switches, and fall back to Force/heuristic removal only when that path is missing or broken.
